# The Huggins Library — instructions for Claude

A home library catalogued from shelf photographs. Static Vite + React + TypeScript
site, no backend. Everything on the page (3D shelves, cover grid, charts, the
constellation graph) derives from one file: `src/data/books.ts`.

If you were asked to add books from photos, use the `/add-books` skill
(`.claude/skills/add-books/SKILL.md`) and follow it exactly.
If you were asked to rebuild or port the app, follow `docs/BUILD-SPEC.md`.

## Commands

- `npm run dev` — dev server on port 5180 (also in `.claude/launch.json`)
- `npm run build` — typecheck (`tsc --noEmit`) + production build; run before committing
- `npm run covers` — Open Library lookup; regenerates `src/data/covers.json`

## Architecture (all under src/)

- `data/books.ts` — the hand-checked catalog. One `Book` per physical volume:
  id (kebab slug), title, author, optional `people[]` (for shared-writer edges),
  publisher, year (first publication of the work), genre (one of the `Genre`
  union), optional `tags[]` (cross-genre threads like `ireland`, `fishing`),
  shelf (1–5), and `spine` (bg/ink hex sampled from the photo, h 0.6–1 relative
  height, w thickness px, kind hardback|paperback, optional lean degrees).
- `data/covers.json` — generated by `npm run covers`. Never edit by hand except
  to DELETE a wrong match; deletions are lost if the script re-runs, so re-check
  its log after running (it prints every match).
- `lib/collection.ts` — derived stats, genre → color mapping, cover URL helpers.
- `lib/constellation.ts` — graph build + deterministic force layout (no
  Date.now/Math.random; seeded PRNG so the sky is stable across visits).
- `components/` — Shelves (3D spines), Collection (grid + filters), Ledger
  (stats + charts), Constellation (SVG graph), AddBooks, BookDialog.

## Rules that are easy to break

1. **The catalog is honest.** A book only enters `books.ts` if its spine is
   legible enough to identify. Partly legible → `uncertain: true` plus a `note`
   saying what was actually readable. Never invent titles, authors, or years.
2. **Genre colors are positional.** The 8 largest genres take the 8 validated
   palette slots in size order (see `lib/collection.ts`); smaller genres share
   the neutral. Do not hand-assign hues or add new ones.
3. **Copy style:** no em-dashes anywhere in visible copy, sentence case, plain
   verbs. Serif (Libre Caslon) for titles and prose, Archivo for UI labels,
   Spline Sans Mono for data/annotations. One accent color (gilt #c9a961).
4. **Spine colors come from the photo**, not from the cover art. Muted, aged
   values fit the shelf; neon values are always wrong.
5. **Performance on the shelf:** cover faces stay `visibility: hidden` and mount
   their image only after first hover (the `warm` state in Shelves.tsx). Do not
   mount 70+ image layers into the 3D scene.
6. Keep `npm run build` green. There is no test suite; the build and a look at
   the dev server are the verification.

## Deploy

Pushes to `main` deploy to Vercel (project `huggins-library`, personal scope).
Manual deploy: `vercel --prod`.

## Repo conventions

- Commits carry the owner's identity only. Never add Co-Authored-By trailers,
  AI attribution, or mentions of Claude to commit messages; the history was
  rewritten once to remove them and should stay that way.
- `README.md` is written for people browsing the repo, not for tooling. Keep
  technical detail in `docs/DEVELOPMENT.md` (day-to-day) and
  `docs/BUILD-SPEC.md` (full spec), and model instructions here.
